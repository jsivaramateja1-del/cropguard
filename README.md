# CropGuard

**Early detection and management of crop diseases and pest infestations.**

A farmer photographs a diseased leaf. CropGuard screens it against a small vision model,
cross-checks the local weather for disease-favourable conditions, returns a qualified
advisory, and places the case on an outbreak map. Uncertain cases go to an agricultural
expert, who can confirm or correct the diagnosis — and the farmer can follow up as the
crop recovers.

Built for **Frontier Demo Day 2026**. The problem statement is inspired by SIH26131
(*Early Detection and Management of Crop Diseases and Pest Infestations*); CropGuard is an
independent prototype, not an SIH submission.

> CropGuard is an early-screening aid, not a replacement for an agricultural expert.
> Results are presented as a *potential diagnosis* and are routed to a human when
> confidence is low. No pesticide dosage is ever generated by this system.

**Live:** [cropguard-blush.vercel.app](https://cropguard-blush.vercel.app) ·
API [cropguard-pzs9.onrender.com](https://cropguard-pzs9.onrender.com/health)

## What actually works

Everything below is implemented and covered by tests. The "Known limits" section further
down is equally honest.

| Capability | Detail |
|---|---|
| Leaf photo → disease | MobileNetV3-Large, fine-tuned from ImageNet-1K V2, 16 classes (10 tomato, 3 potato, 3 rice) |
| Serving | ONNX Runtime, 16.8 MB artifact, ~20 ms/inference on 2 vCPU, 151 MB RSS (fits a 512 MB free tier) |
| Weather risk | Open-Meteo primary, MET Norway fallback, deterministic 0–9 point scale + advisory adjustment, 10-minute cache |
| Advisory | 21-entry knowledge base, no invented dosages, viruses and mites flagged as not chemically treatable |
| Reports | Persisted in Supabase Postgres; public reference `CG-00042` plus a one-time access code |
| Expert review | Queue, confirm/correct with notes, append-only audit trail |
| Accounts | Farmer self-registration, bcrypt passwords, JWT sessions, revocation |
| Expert approval | Farmers apply; an admin approves, which promotes the account and invalidates old tokens |
| Follow-up | Reference + access code, condition status, optional photo, full timeline |
| Outbreak map | Public `/api/outbreaks` with coordinates rounded to ~1 km; Leaflet, lazy-loaded |
| Security | Anonymous farmers with scoped tokens, bearer-token staff auth, ownership checks, rate limiting, content-based upload validation |

## Measured, not claimed

- **36/36** correct on 36 labelled PlantVillage photographs (12 classes × 3), run against
  the exact ONNX artifact the backend serves — see [docs/verification.md](docs/verification.md)
- **0.9976** best validation accuracy, **0.9676** macro recall on a 20,432-image training run
  (Tesla T4, 12 epochs) — but see the leakage caveat in [docs/model-card.md](docs/model-card.md)
- Confidence calibration measured: median 0.907, 5th percentile 0.880 — [docs/calibration.md](docs/calibration.md)
- **141** backend tests, **14** frontend error-handling checks, **21** render checks, 4 CI jobs

## Known limits

Stated plainly because a demo that hides these is worth less than one that names them:

- **Rice has no healthy class.** The model cannot confirm a rice leaf is healthy; the API
  says so in the response and `/api/model` reports `healthy_class_available.Rice: false`.
- **Wheat is not supported.** It appears in the advisory knowledge base but has no trained
  classes, so the backend refuses a wheat submission rather than mislabelling another
  crop's prediction.
- **No "not a plant" output.** The classifier is a closed 16-way softmax. Two mitigations
  exist — a foliage-colour check and a confidence floor at 0.88 — and neither is a real
  out-of-distribution detector. A bird on a branch still passes the colour check.
- **Not field-validated.** Accuracy figures come from PlantVillage lab images, the same
  source the model trained on. Phone photos of real field leaves will score lower, and no
  number for that exists yet.
- **Shared expert token, not user accounts.** One secret per role: no registration, no
  per-expert revocation, no attribution between two experts using the same token.
- **Uploads are local-disk** unless Cloudinary is configured, so images do not survive a
  redeploy even though the database rows do.
- **End-to-end tests are mocked by default.** 44 Playwright checks run against a mocked
  API on desktop and mobile; the live suite exists but is not part of CI, because it
  depends on a free-tier host that sleeps.

## Architecture

```
   farmer's phone
   ┌──────────────────────────────┐
   │ React 18 + Vite + Tailwind   │   Vercel
   │ camera · Leaflet · expert UI │
   └──────────────┬───────────────┘
                  │ HTTPS REST
   ┌──────────────▼───────────────┐
   │        FastAPI backend       │   Render (free tier)
   │ auth · validation · routing  │
   └──┬────────┬─────────┬────────┘
      │        │         │
   ┌──▼─────┐ ┌▼──────┐ ┌▼──────────────┐
   │ ONNX   │ │Open-  │ │ Supabase      │
   │ Mobile │ │Meteo  │ │ Postgres      │
   │ NetV3  │ │+ MET  │ │ reports,      │
   │ 16 cls │ │Norway │ │ follow-ups,   │
   └────────┘ └───────┘ │ audit_events  │
                        └───────────────┘
```

The backend loads whatever `.onnx` + `class_names.json` pair sits in `backend/model/`, so a
retrained model drops in without a code change.

## Run locally

```bash
# backend
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt          # includes onnxruntime
cp .env.example .env                     # SQLite by default, no cloud needed
uvicorn main:app --reload                # http://localhost:8000/docs

# frontend
cd frontend
npm install
cp .env.example .env.local               # VITE_API_BASE_URL=http://localhost:8000
npm run dev                              # http://localhost:5173
```

Tests:

```bash
cd backend  && python -m pytest tests -q          # 183 tests
cd frontend && npm run test:errors && npm run test:render

# End-to-end (Playwright). The default suite mocks the API and needs no backend.
cd frontend && npx playwright install chromium && npm run build && npm run test:e2e

# Against the real deployment — the only suite that can catch deployment-level faults
# such as a missing SPA rewrite or a CORS misconfiguration.
E2E_BASE_URL=https://cropguard-blush.vercel.app npm run test:e2e:live
```

## Environment

| Variable | Required | Purpose |
|---|---|---|
| `DATABASE_URL` | no (defaults to SQLite) | Postgres in production. **Percent-encode special characters in the password** — an unencoded `@` silently breaks the host |
| `EXPERT_TOKEN` | for review | Bearer token for expert endpoints. No default: unset means no privileged access |
| `ADMIN_TOKEN` | optional | Same powers, operational use |
| `FRONTEND_ORIGIN` | yes in production | Allowed browser origin; single-label wildcards supported |
| `MODEL_PATH` | no | Path to the ONNX artifact |
| `CONFIDENCE_THRESHOLD` | no (0.75) | Below this, a report goes to expert review |
| `OOD_CONFIDENCE_FLOOR` | no (0.88) | Below this, the photo may not be a leaf |
| `CLOUDINARY_*` | optional | Durable image storage |

## Status

**Core functionality verified; security and regression tests passing; deployed and
healthy.** Not production-ready as a complete product — the gaps listed under *Known
limits* are real. Specifically: no field-accuracy measurement, no per-user accounts, no
end-to-end browser suite, and local-disk image storage.
